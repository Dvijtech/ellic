# ELLIC — Turn Control Firmware

Прошивка ESP32, управляющая двумя колёсными приводами ODrive по сигналу с энкодера AS5600 на валу руля, с ручным доводом поворота через тормозные ручки.

## Платформа

```ini
[env:mhetesp32devkit]
platform = espressif32@6.8.1
board = mhetesp32devkit
framework = arduino

lib_deps =
    RobTillaart/AS5600
    lemmingDev/ESP32-BLE-Gamepad
```

## Идея работы

1. Датчик **AS5600** на валу читает угол поворота руля (0–360°) и превращает его в непрерывный (не обрезающийся на границе 0/360) угол.
2. Непрерывный угол переводится в целевое число оборотов колёсных моторов через передаточное число `GEAR_RATIO`.
3. Целевая позиция отправляется на оба привода **ODrive** по UART в закрытом контуре позиции (`input_pos`).
4. Левое и правое колесо крутятся в **противоположные стороны** относительно вала — это заложено в знаках при расчёте целевой позиции (моторы стоят зеркально).
5. Если водитель зажимает **тормозную ручку**, и руль находится в "зоне поворота" (около 0°/360° или 180°) — соответствующее колесо отключается от общей логики и начинает **доворачиваться вручную**, шагами `TURN_STEP`, пока тормоз зажат. Второе колесо продолжает работать штатно.
6. При отпускании тормоза накопленный доворот фиксируется как постоянное смещение (`holdOffset`) и логика возвращается к обычному режиму.
7. Отдельно отслеживается живость каждого ODrive (пропадание/восстановление питания) — при восстановлении привод переинициализируется и возвращается в закрытый контур.

## Структура файлов

```
src/
├── main.cpp              — сборка всех модулей, setup()/loop()
├── Encoder.h              — обёртка над AS5600
├── ODriveUART.h/.cpp      — общение с одним приводом ODrive по UART
├── PhaseDetector.h/.cpp   — чтение тормозных ручек, определение "зоны поворота"
├── MotionController.h/.cpp — основная логика движения и ручного доворота
├── Debug.h/.cpp           — весь вывод в Serial, отдельно от логики
└── BLETrigger.h/.cpp      — BLE-геймпад (заглушка, требует доработки)
```

### `Encoder`
Инициализирует AS5600 на заданных пинах I2C, читает угол и накапливает **непрерывный угол** (`continuousAngle`) — то есть при переходе через 0°/360° не происходит скачка. Именно это значение, умноженное на передаточное число, задаёт целевую позицию моторов.

- `begin(sda, scl)` — инициализация, проверка магнита.
- `update()` — вызывается каждый `loop()`, обновляет `rawAngle` и `continuousAngle`.
- `resetBaseline()` — сбрасывает точку отсчёта дельты угла (не сбрасывает накопленный `continuousAngle`).

### `ODriveUART`
Инкапсулирует управление одним приводом: отправку целевой позиции, переключение состояний (idle/closed loop), проверку связи (`checkAlive` — пингует `r vbus_voltage` и ждёт ответ 100 мс) и восстановление после пропадания питания (`reinit`).

Создаётся два экземпляра — `leftDrive` и `rightDrive`, на `Serial1` и `Serial2` соответственно.

### `PhaseDetector`
Читает состояние двух тормозных ручек (`INPUT_PULLDOWN`) и определяет, находится ли текущий угол вала в "зоне поворота" — там, где разрешён ручной доворот:
- около 0° / 360° (±10°)
- около 180° (±10°)

### `MotionController`
Главная логика. На каждом шаге управления (период `CONTROL_PERIOD`, по умолчанию 50 мс):

- **Оба тормоза зажаты** — оба привода в idle.
- **Зажат только левый тормоз** (в зоне поворота) — левый привод в idle, правый доворачивается вручную с шагом `TURN_STEP`.
- **Зажат только правый тормоз** (в зоне поворота) — правый привод в idle, левый доворачивается вручную с шагом `TURN_STEP` в противоположную сторону.
- **Тормоза не зажаты** — оба привода в закрытом контуре, едут по целевой позиции от энкодера + накопленное смещение доворота (`holdOffset`).

Знаки, определяющие направление вращения (подобраны экспериментально под конкретную сборку):
- Общее направление вращения обоих колёс от угла вала — знак минус перед `_encoder.continuousAngle()` при расчёте `_targetTurnsV`.
- Левое/правое колесо крутятся зеркально друг другу за счёт разных базовых знаков (`+targetTurnsV` для левого, `-targetTurnsV` для правого).
- Доворот при зажатом правом тормозе вычитается (`-= _turnStep`), при зажатом левом — прибавляется (`+= _turnStep`), чтобы левое и правое колесо доворачивались в противоположные стороны.

### `Debug`
Весь `Serial.print`/`println` вынесен сюда, чтобы не засорять логику. Периодически (`PRINT_PERIOD`, по умолчанию 100 мс) выводит строку состояния:

```
RAW:<угол вала> TARGET:<целевые обороты> LB:<левый тормоз> RB:<правый тормоз> Z:<в зоне поворота?> LO:<смещение слева> RO:<смещение справа>
```

Плюс отдельные методы для логов инициализации/переподключения ODrive.

### `BLETrigger` — требует доработки
Пустой на момент рефакторинга. В `main.cpp` вызывается `BLETrigger_begin()` и `BLETrigger_update()`, но их реальное содержимое нужно написать — сейчас там временная заглушка на базе `ESP32-BLE-Gamepad`.

## Настройки (`main.cpp`)

| Константа | Значение | Смысл |
|---|---|---|
| `GEAR_RATIO` | 4.4 | Передаточное число вал → колесо |
| `TURN_STEP` | 0.03 | Шаг доворота колеса за одну итерацию управления при зажатом тормозе |
| `CONTROL_PERIOD` | 50 мс | Период пересчёта и отправки целевой позиции на приводы |
| `PRINT_PERIOD` | 100 мс | Период отладочного вывода в Serial |
| `ODRIVE_CHECK_PERIOD` | 1000 мс | Период проверки связи с ODrive |
| `ODRIVE_BOOT_DELAY` | 1500 мс | Задержка перед переинициализацией привода после восстановления питания |

| Назначение | Пин |
|---|---|
