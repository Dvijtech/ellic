ТЗ: переработка телеметрии ELLIC (v2 протокола)
1. Цель
1.	Убрать «стену текста»: прошивка отдаёт только компактные строго структурированные записи без названий полей.
2.	Ошибки (AS5600/I²C, CAN, ODrive) не ломают структуру потока: они передаются счётчиками в отдельной записи, а не текстовыми сообщениями.
3.	На стороне компьютера EllicBleTelemetryBrowser.html показывает онлайн графики всех числовых переменных и ошибок вместо списка значений. На экране только графики и кнопки.
4.	По кнопке из EllicBleTelemetryBrowser.html  полученные данные превращается напрямую в .xlsx (без промежуточного CSV): время слева направо, один столбец = одна единица времени в соответствии с настройками пердчи данных, каждая переменная и каждый тип ошибки — отдельная строка. Все делается на одном листе эксель.
2. Что не меняется
•	Каналы доставки: Serial и BLE получают один и тот же текст из Telemetry::emit().
•	Управление моторами не зависит от телеметрии (раздел 14.3 спецификации).
•	Состав модулей (раздел 0 спецификации) — новых классов нет.
3. Протокол записей (прошивка → компьютер)
Текст, одна запись = одна строка (\n), поля через запятую, порядок полей фиксирован, имён полей нет. Первое поле — тип записи, второе — ts (millis() ESP32 в мс на момент сбора).
Период: одна пачка из записей M, L, R, E каждые TELEMETRY_PERIOD_MS = 200 мс.
M — вал и движение
M,ts,raw,cont,delta,valDelta,mode,flags,leftWheelDelta,rightWheelDelta
Поле	Формат	Смысл
raw	%.1f	сырой угол AS5600, °
cont	%.1f	накопленный угол, °
delta	%.2f	последняя дельта энкодера, °
valDelta	%.2f	ValDelta последнего цикла управления, °
mode	0/1/2	0=NORMAL, 1=CALM, 2=TURN
flags	битовая маска	бит0 левый тормоз, бит1 правый тормоз, бит2 TURN_ZONE
leftWheelDelta / rightWheelDelta	%.3f	приращения, обороты мотора
L / R — колесо (левое / правое)
L,ts,online,state,traj,iq,vel,vbus,ibus,axisErr,motorErr,encErr,ctrlErr,tx,rx
Поле	Формат	Смысл
online	0/1	канал на связи
state	int	Axis_State
traj	0/1	Trajectory_Done_Flag
iq	%.2f	Iq_Measured, А
vel	%.3f	Vel_Estimate, об/с
vbus / ibus	%.2f	напряжение/ток шины
axisErr, motorErr, encErr, ctrlErr	hex без 0x	текущие коды ошибок ODrive (статус, не счётчики)
tx, rx	uint	счётчики кадров
E — счётчики ошибок (накопительные с включения)
E,ts,as5600,lTxFail,rTxFail,lStale,rStale,lOffline,rOffline,lAxisErr,rAxisErr,lMotErr,rMotErr,lEncErr,rEncErr,lCtrlErr,rCtrlErr
Счётчик	Что считает
as5600	неудачные чтения AS5600 (< 2 байт или ошибка шины)
lTxFail / rTxFail	отказ twai_transmit() при Set Input Pos
lStale / rStale	команда пропущена: позиция колеса недоступна/устарела (прежний rxFailCount)
lOffline / rOffline	переходы канала в offline
l/r AxisErr, MotErr, EncErr, CtrlErr	новые ненулевые значения ошибки ODrive (смена кода на другой ненулевой). Постоянно висящая ошибка = одно событие, её код виден в записи L/R
Счётчики не накопительные и считаются в каждой выдаче то количество событий которое произошло конкретно за период постшествующий с предыдущей выдачи. Счетчики не накапливаются.
G — лог (редкие события, текст) 
G,ts,level,module,msg — level: 0=INFO, 1=WARNING, 2=ERROR, 3=CRITICAL; msg может содержать запятые (берётся всё после 4-й запятой). Сюда остаются только редкие события (online/offline каналов, старт системы). Повторяющиеся ошибки сюда не пишутся — они считаются в E. Перемести в E и сделай по такому же принципу. Раздел G исключи.

5. Приёмник: EllicBleTelemetryBrowser.html
Один файл, без внешних библиотек (работает офлайн).
Источники данных
•	Web Bluetooth (как сейчас, Nordic UART); 
•	По нажатию на кнопку делает сохранение полученных данных Excel.
Онлайн-графики (окно 30 с / 1 мин / 5 мин / всё, пауза)
•	вал: raw, cont, delta;
•	движение: valDelta, leftWheelDelta, rightWheelDelta;
•	для каждого колеса: Iq, vel, Vbus, Ibus;
•	ошибки: количество в секунду тремя графиками — «вал и CAN», «ODrive левый», «ODrive правый».
•	Статусные и логические величины (online, state, traj, mode, тормоза, TURN_ZONE, коды ошибок) —  точки на графиках.  не отдельная панель индикаторов. Интегрированы в общие графики.
•	Никаких отдельных панелей все выводится на одной панели.
Экспорт Excel (.xlsx) — кнопка «Скачать Excel», файл формируется в браузере.
•	Лист «Данные»: строка 1 — выбранные интервалы времени от старта (0, 1, 2, …), строка 2 — время суток это что за хуйня? Убратьвремя суток; столбец A — имя переменной, далее по одному столбцу на секунду.
•	Строки величин: значение — последнее принятое в эту секунду.
•	Строки ошибок: число событий в эту секунду (0, если пакеты были, но ошибок нет; пусто, если пакетов в эту секунду не было). Строки ошибок вынесены в нижний блок.
•	Строки статусов (online, state, mode, тормоза и т.д.) — тоже в таблице, как числа.
•	Все на одном листе записи G (секунда, уровень, модуль, текст и так далее).
•	Время — по ts устройства, а не по приходу в BLE; перезагрузка ESP32 в середине записи не рвёт ось времени.
•	Ограничение Excel: 16 384 столбца ≈ 4,5 часа записи на файл.
•	Дополнительно: «Сохранить сырой лог» (.txt) для повторного разбора.
6. Критерии приёмки
1.	Serial-вывод — только строки M/L/R/E/G, ~220 байт на период, имён полей нет.
2.	Обрыв I²C AS5600 или остановка питания одного ODrive не порождает строк другого формата; можно убрать итоговые счетчики. Итоговые счетчики будем делать в аналитике ее пока не обсуждаем. Будем обсуждть потом не в эту итерцию
3.	На графиках видны все числовые величины; графики ошибок показывают счётчик в моменте выдачи.
4.	Файл .xlsx открывается в Excel без конвертации; ошибки читаются как строки с числами на пересечении с секундой.
5.	Отключение BLE/Serial-канала не влияет на moveLeftWheel/moveRightWheel.
7. Принятые допущения (можно поменять)
•	Период 200 мс (5 Гц) — достаточно для графиков; в Excel ничего не агрегируется. Все выдается как есть один в один.
•	В секунде для величин берётся последнее значение, не среднее (для угла среднее некорректно из-за перехода 0/360°).
•	Скорость Serial 115200 хватает (≈ 1,1 КБ/с);
