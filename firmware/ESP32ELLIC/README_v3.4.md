# ELLIC v3.4 — что изменилось и как накатить

Причины (лог RA.xlsx от 04.11, v3.3, ELLIC неподвижен):
- тормоза: ~1300 (L) и ~570 (R) отброшенных импульсов в секунду; фильтр v3.3 при такой помехе не мог принять **отпускание** → тормоз залипал, вал стоял в `TURN_ZONE` (≈1°) → поворот на каждом цикле после отпускания;
- кнопка стрельбы: `fire = 1` весь лог, `fire_count = 0` (нет фронтов — нечего считать);
- BLE: 22 провала по 1.4–1.8 с, очередь 6 пакетов ≈ 1.2 с; при переполнении терялись новые пакеты, старые доезжали с задержкой.

## Файлы в этом архиве (скопировать в `firmware/ESP32ELLIC/MAIN/src/`)

| Файл | Что |
|---|---|
| `InputFilter.h` | **новый**: интегрирующий фильтр входа (накопитель растёт при LOW, убывает при HIGH; смена состояния на краях) |
| `BrakeInputs.h/.cpp` | используют `InputFilter`; интерфейс и снапшот те же |
| `FireButton.h/.cpp` | используют `InputFilter`; интерфейс и снапшот те же |

Проверка фильтра на ПК (имитация: помеха ~1300 имп/с при разомкнутом контакте, нажатие 1 с, ложный «тап» 10 мс): новый фильтр принимает нажатие через ~30 мс, отпускание через ~80 мс, тап 10 мс отбрасывает; старый фильтр v3.3 нажатие принимает, а **отпускание не принимает никогда**.

## Правки в существующих файлах (3 места)

**1. `Config.h`** — версия:
```
#define FW_VERSION "v3.4"
```

**2. `BleTelemetry.h`** — очередь короче (макс. задержка ≈ 3 × 200 мс):
```
static const int QUEUE_LENGTH = 3;          // ~0.6 с запаса при периоде 200 мс
```

**3. `BleTelemetry.cpp`**, в конце `send()` заменить
```
    // Таймаут 0: если очередь занята/полна - пакет тихо теряется, но
    // loop() ни при каких обстоятельствах не ждёт.
    xQueueSend(_queue, &item, 0);
```
на
```
    // Таймаут 0: loop() ни при каких обстоятельствах не ждёт. Если очередь
    // полна, выбрасываем САМЫЙ СТАРЫЙ пакет, а не новый: в браузер должны
    // доезжать свежие данные, а не пакеты секундной давности.
    if (xQueueSend(_queue, &item, 0) != pdTRUE) {
        QueueItem dropped;
        xQueueReceive(_queue, &dropped, 0);
        xQueueSend(_queue, &item, 0);
    }
```

`MotionController.*`, `Encoder.*`, `ODriveCAN.*`, `Telemetry.*`, `main.cpp`, формат записей и просмотрщик **не меняются**.

## Проверка

1. В Serial: `# ELLIC firmware v3.4`.
2. Мультиметром относительно **GND ESP32**, ESP включена, ничего не нажато: GPIO32, GPIO33 (ждём ~3.3 В), GPIO23 (записать значение). Нажатие: около 0 В.
3. Лог (xlsx) + параллельно Serial в файл: 30 с без нажатий; левый тормоз 1 с; пауза 3 с; правый 1 с; 5 нажатий пушки.
4. Смотреть: `тормоз L/R` в M совпадают с нажатиями и отпускаются сразу; `fire_count` = 5; `lBrakeGlitch`/`rBrakeGlitch` (шум остаётся, пока не исправлена проводка — фильтр его просто не пропускает); задержка в браузере против Serial.

Если после фильтра задержка отпускания тормоза заметна или помеха по счётчикам не уменьшилась после 100 нФ на пин — следующий шаг 1 мкФ на пин и проводка (витая пара, возврат на GND у ESP).
